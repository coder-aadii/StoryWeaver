# StoryWeaver HTTP API

> Index of the versioned REST API served by `apps/api` (FastAPI).

## Status

**Partially implemented.** Health endpoints and generic CRUD for 10 resource groups are implemented and tested. Custom operations (import, generate, regenerate, render, search) are **Planned — not implemented**. No authentication.

- Base URL (dev): `http://localhost:8000/api/v1`
- Interactive docs: `http://localhost:8000/docs`, schema: `/openapi.json` (generated by FastAPI, always current)
- Conventions: [API-conventions](API-conventions.md) · [errors](errors.md) · [pagination](pagination.md) · [authentication](authentication.md)

### Renders (no separate doc)

`/renders` follows the generic pattern. Create body: `{"project_id": "<uuid>"}`; patch body: `{"status": "queued|rendering|completed|failed"}`. Read fields: `id, created_at, updated_at, project_id, status, output_asset_id, error`. Creating a render row **does not start a render**; the render workflow is Planned ([workflows/render-workflow](../workflows/render-workflow.md)). The `timeline` column and the `started_at`/`finished_at` timestamps are not exposed (only `created_at`/`updated_at` are).

## Generic resource contract

For each CRUD group `X`: `GET /X` (list), `GET /X/{id}`, `POST /X` (201), `PATCH /X/{id}`, `DELETE /X/{id}` (204). Implemented once in `apps/api/app/api/crud.py` ([adding-an-api-resource](../development/adding-an-api-resource.md)).

Constraints of the generic contract (explicit `null` only clears nullable columns and is a 422 elsewhere, length limits on updates, single-UUID-key tables only, no filters/`PUT`/nesting): [API-conventions](API-conventions.md), [errors](errors.md).

Per-resource request/response examples are in each [resource doc](resources/projects.md).

## Quick example

```bash
curl -s -X POST localhost:8000/api/v1/projects -H 'content-type: application/json' -d '{"title":"Ice Age"}'
curl -s localhost:8000/api/v1/projects?limit=10
```
