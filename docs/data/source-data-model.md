# Source Data Model

> Tables and contracts for the source library: channels, videos, transcripts, chunks, topics, collections.

## Status

**Implemented for the Source Library V1 path (P1, 2026-10-01); topic/collection membership is not.** The ingestion service populates `channels`, `source_videos`, `transcripts` and `transcript_chunks` and records background runs in `workflow_runs`. Channel scan/import/sync, embeddings, topic links and collection-membership endpoints are Planned. Product design: [domains/source-library](../domains/source-library.md); column-level detail: [database-schema](database-schema.md).

## Entities

| Entity | Identity | Key fields | Notes |
| --- | --- | --- | --- |
| `Channel` | unique `(platform, external_id)` | `title`, `url`, `status`, `video_count`, `error`, `metadata` | Upserted by the ingestion service from a video's **canonical channel id** (`UC…`, never an `@handle`) with `url` = `https://www.youtube.com/channel/<id>`; `video_count` stays NULL until a future scan (P11) |
| `SourceVideo` | unique `(platform, external_id)` | `kind` (`youtube`/`transcript`), `url?`, `fingerprint?`, `thumbnail_url?`, `title`, `description`, `duration_seconds`, `published_at`, `language`, `status`, `error`, `metadata`, `channel_id?` | One row however many projects use it. YouTube: `external_id` = 11-char video id. Uploads: `platform='upload'`, `external_id` = fingerprint, `url` NULL, `reference_url` (text only) in `metadata` |
| `Transcript` | unique `(source_video_id, version)`; one `is_current` per source | `status`, `origin`, `language`, `text` (cleaned), `segments`, `version`, `is_current`, `raw_storage_key`, `raw_sha256`, `normalizer_version`, `error` | Versions are created only by the ingestion service; history rows are kept ([KI-13](../reference/status.md#known-issues-and-limitations), resolved) |
| `TranscriptChunk` | unique `(transcript_id, chunk_index)` | `text`, `start_seconds?`, `end_seconds?`, `token_count`, `embedding`, `embedding_model`, `search_vector` | The unit of retrieval; `search_vector` is generated by Postgres (keyword search); `embedding`/`token_count` stay NULL |
| `WorkflowRun` | unique `idempotency_key`; one active run per `(kind, subject_id)` | `kind`, `subject_type`, `subject_id`, `status`, `attempt`, `params`, `progress`, `error` | Persisted background job (`source.add`, `source.fetch_transcript`) that carries import status for the UI; not a library entity itself ([ingestion workflow](../workflows/ingestion-workflow.md)) |

## Pydantic contracts (implemented)

In `apps/api/app/schemas/source.py`:

- `SourceRef` — what a URL points at, derived **without network**: `platform`, `external_id`, `kind`, `canonical_url` (`SourceExtractor.identify`).
- `NormalizedSource` — platform-neutral output of `SourceExtractor.extract` (metadata only): `platform`, `kind` (`video|channel|playlist|transcript|file`), `external_id`, `url`, `title`, `description?`, `duration_seconds?`, `published_at?`, `language?`, `thumbnail_url?`, `channel_external_id?` (canonical id), `channel_title?`, `channel_url?`, `segments` (unused by `extract`), `extra` (small whitelist). YouTube specifics stop here.
- `ExtractedTranscript` — a transcript as obtained, before normalization: `segments`, `language?`, `origin` (`manual|auto|upload`), `raw` bytes exactly as received, `raw_ext` (`json3|vtt|srt|txt`).
- `TranscriptSegment` — `start?`, `end?` (null for plain text; `end ≥ start` when both present), `text`, `speaker?`.

JSON Schema is exported to `packages/schemas/` by `make schemas`. API response models are in `apps/api/app/schemas/source_api.py` ([sources API](../api/resources/source-videos.md)).

## Transcript representation

- **Raw** — the file exactly as received (caption `json3`/`vtt`, or the uploaded/pasted `srt`/`vtt`/`txt`), stored via `LocalStorage` at `transcripts/<source_id>/v<n>/raw.<ext>`; key and sha256 on the transcript row. Never mutated.
- **Cleaned** — `text` (normalized segments joined with single spaces; a blank line between untimed paragraphs) and `segments` (JSONB list of timestamped segments) in the database, produced by the deterministic normalizer (`normalizer_version`).
- `origin` — `manual` / `auto` (platform captions) or `upload`; `unknown` only on failed placeholder rows. Not a database enum.
- Chunking: `chunk_segments(segments, max_chars=1200)` returns `(text, start, end)` tuples (times may be `None`); the service writes them to `transcript_chunks` in the same transaction as the transcript version.

## Organisation

- `topics`: `name`, `slug`, `description` — flat, no hierarchy, no link to videos/chunks yet.
- `collections` + `collection_videos`: many-to-many with videos. **No API endpoint adds/removes members** (table only).
- Duplicate detection: the unique `(platform, external_id)` constraint plus a pre-insert lookup (adding the same video again returns the existing source), and an **exact content fingerprint** across formats and platforms. Near-duplicate detection (re-uploads, edits): *Planned — not implemented* (P12).

## Status lifecycle

`SourceStatus`: `discovered → importing → imported | failed`. `imported` means **metadata stored** (see [workflows/ingestion-workflow](../workflows/ingestion-workflow.md)); a source is *searchable* when its current transcript is `ready` and has at least one chunk — that is derived, not a status value (semantic search will additionally need embeddings, P11). `TranscriptStatus`: `pending → processing → ready | failed`. Transitions are not enforced by code; the API allows PATCHing any valid status.

## Source usage and idea reuse — storage direction (Decision pending)

Goal ([domains/source-library](../domains/source-library.md)): remember which sources, facts and ideas have been used by which project, so later work can avoid repeating them or find unused material ("unused ideas in my History collection"). Only project-level usage (which project links which source) is stored today; the options below add what was used from it.

| Option | Shape | Notes |
| --- | --- | --- |
| 1. Source-level usage only | add usage metadata to `project_sources` (e.g. `role`, `used_at`) | Cheap; says *that* a source was used, not *what* from it |
| 2. Usage records | new `source_usages` table: `source_video_id`, optional `transcript_chunk_id` / time range, `project_id`, optional artifact id (the story candidate or script it fed), `kind` (fact / idea / story), timestamps | Answers "which parts of this source were used where"; needs an artifact model to reference ([story-data-model options](story-data-model.md#story-candidate-and-source-analysis-storage-options-decision-pending)) |
| 3. Idea embeddings | store an embedding per accepted idea/story summary and compare new candidates against them | Enables "avoid previously used ideas" semantically rather than by exact match; design in [embeddings-and-vector-search](embeddings-and-vector-search.md#originality-and-similarity-data-direction) |

Options 2 and 3 are complementary. None is chosen; *Deferred until required by the production workflow*.
