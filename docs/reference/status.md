# Implementation Status Matrix

> The canonical statement of what StoryWeaver does today versus what is only designed. Other documents link here instead of restating status.

## Status

Implemented (this document is maintained against the code; see [How to update](../README.md#how-to-update-the-documentation)).

**Legend.** *Implemented* = exists, runs, and has automated tests or a manual verification noted. *Partially implemented* = some pieces exist (interfaces, schema, adapters) but no working end-to-end feature. *Planned* = designed, no code. *Future/Deferred* = intentionally postponed until the production workflow needs it.

Last verified against the repository: 2026-10-01 (after P1 Source Library V1; see the changelog).

## Verification record

Initial foundation (2026-10-01): `make lint` clean; pytest 35 passed against Postgres 16 + pgvector 0.6.2; Vitest 10 passed; Playwright 2 passed; `next build` succeeded; sample render produced a 6.5 s 1280×720 H.264 MP4.

After P0 (2026-10-01): `make lint` clean; pytest 232 passed with `TEST_DATABASE_URL` set (220 passed + 12 skipped without it); Vitest 21 (web 7, video 14); Playwright 2; fixture render with a real image and WAV verified with Remotion's bundled ffmpeg/ffprobe ([ADR-009](../decisions/ADR-009-render-asset-resolution.md)). Provider adapters remain mock-tested only.

After P1 Source Library V1 (2026-10-01): `make lint` clean; pytest 505 passed with `TEST_DATABASE_URL` set; Vitest 101 (web 87, video 14); Playwright 3 (including the upload → search → duplicate-notice flow); `next build` succeeded. Counts live in [testing strategy](../testing/testing-strategy.md). **Live YouTube check (one run, recorded exactly):** one real public video (`jNQXAC9IVRw`) added through the real API with yt-dlp 2026.8.19 and a local Postgres — title, channel, 19 s duration, thumbnail and language were fetched, and the **manual** English captions (json3) were downloaded: 6 segments, 1 chunk, searchable (a word from the transcript was found at 1.2 s), only a 918-byte raw caption file stored, no media, and adding the same video via another URL form was a no-op. **Not verified live:** videos with automatic captions only, long videos, other languages, private/blocked videos (these paths are covered only by recorded/synthetic fixtures).

## Known issues and limitations

> Canonical list of defects and gaps found by auditing the code. Other documents link here (`status.md#known-issues-and-limitations`) instead of restating them. Entries marked **Resolved in P0** were fixed in code on 2026-10-01 and are kept as history so IDs stay stable; the rest describe current behavior and are tracked in the [implementation plan](../../implementation-plan/IMPLEMENTATION_PLAN.md#progress-tracker). IDs are stable; do not renumber.

| ID | Area | Limitation (current behavior) |
| --- | --- | --- |
| KI-1 | Configuration | **Resolved in P0 (2026-10-01).** An empty or blank `STORAGE_ROOT` now means "unset" and resolves to `<repo>/data`; relative values resolve against the repository root, not the working directory. `.env.example` no longer sets it (commented out). Test: `tests/test_config.py`. |
| KI-2 | Logging | **Resolved in P0 (2026-10-01).** A log key is treated as secret only when its *final word* is a secret word (`api_key`, `secret`, `password`, `authorization`, `credential(s)`, `bearer`, `token`/`access_token`/…), so `output_tokens` and `max_tokens` are logged as numbers. String values — including nested dicts/lists and exception text — are scrubbed for secret-shaped substrings (`sk-…`, `AIza…`, `AQ.…`, `ghp_…`, `xox…`, SendGrid `SG.…`, `Bearer …`, `user:password@` in URLs). Redaction is best-effort: never log prompts or bodies at INFO. Tests: `tests/test_logging.py`. |
| KI-3 | Providers | **Resolved in P0 (2026-10-01).** Every failure inside a provider call becomes a `ProviderError` subclass: `ProviderTimeoutError`, `ProviderResponseError` (empty, blocked, malformed or non-JSON replies, including Google replies with no candidates/parts) or plain `ProviderError` (HTTP/transport, with `.status_code`). Messages carry only provider name, exception type and status — no URL, body or headers. `generate_structured` retries on `ProviderResponseError` and validation errors. Timeout is configurable (`LLM_TIMEOUT_SECONDS`). Verified by a shared **mocked-HTTP** contract suite (`tests/test_provider_contract.py`) for all five LLM adapters and both embedding adapters — this is not live-service testing. |
| KI-4 | API | **Resolved in P0 (2026-10-01).** `PATCH` with an explicit `null` on a NOT NULL field returns `422` (nullable fields — descriptions, `video_count`, transcript `text` — still accept `null` to clear them). Update schemas have length limits, create schemas gained maximum lengths, and a database `DataError` maps to `422 invalid_value`. Tests: `tests/test_api_hardening.py`. |
| KI-5 | Health | **Resolved in P0 (2026-10-01).** `GET /health/ready` logs `health.ready.failed` (exception type + sanitised detail) and its `503` body includes `"error": "<ExceptionType>"` (type only — no host or user). The engine has a connect timeout (`DB_CONNECT_TIMEOUT_SECONDS`, default 10). Tests: `tests/test_api_hardening.py`. |
| KI-6 | Schema | **Mitigated in P0 (2026-10-01).** `Settings.embedding_dimensions` (768) and the `EMBEDDING_DIM` constant that fixes the `vector(768)` column are still independent, and the setting is read by no code. A test (`tests/test_config.py`) now fails if the two defaults diverge. A runtime guard remains planned before embeddings are written (P11). |
| KI-7 | Contracts | **Mitigated in P0 (2026-10-01).** `scripts/export_schemas.py` emits canonical valid/invalid sample documents to `packages/schemas/samples/`; `apps/api/tests/test_timeline_contract.py` (Pydantic) and `packages/video/src/contract.test.ts` (zod) both check them, so a one-sided change fails `make test`. The zod mirror now defaults `camera`, uses the same `shot` enum and an integer `version`. **Remaining:** Pydantic `Timeline.fps`/`width`/`height` have no positivity constraint (zod requires > 0). The Remotion `zod` version warning is resolved: `zod` is pinned to exactly 4.5.4 in `packages/video` and `apps/web`. |
| KI-8 | API | **Resolved in P0 (2026-10-01).** `install_exception_handlers` maps domain errors to HTTP with a uniform body `{"detail", "code"}`: `InvalidSourceError`→422 `invalid_source`, `UnsafePathError`→400 `unsafe_path`, `FileTooLargeError`→413 `file_too_large`, `ProviderNotConfiguredError`→409 `provider_not_configured`, `ProviderTimeoutError`→504 `provider_timeout`, `ProviderResponseError`→502 `provider_bad_response`, other `ProviderError`→502 `provider_error`, any other `StoryWeaverError`→500 `internal_error` (generic message). FastAPI's own request-validation 422 keeps its default body (a list under `detail`, no `code`). |
| KI-9 | Wiring | **Partly resolved in P1 (2026-10-01).** `LocalStorage` is now used by the ingestion service and routes (raw transcripts, delete) and `LocalRunner` runs the ingestion workflows. `LocalStorage.put` raises the typed `FileTooLargeError` (mapped to 413) over the size cap and removes the partial file. **Still open:** no endpoint serves files from `data/` (see KI-17), and there is no upload endpoint for images/audio. |
| KI-10 | Process | No CI exists. All checks run locally (`make lint`, `make test`). |
| KI-11 | Tests | **Resolved in P0 (2026-10-01).** The DB fixtures reset the cached settings, engine and sessionmaker before and after the session, and the whole test session overrides the real `DATABASE_URL`, so tests no longer depend on execution order. Test: reverse-order runs pass. |
| KI-12 | Validation | **Resolved in P0 (create endpoints) and P1 (2026-10-01).** In P0, `POST /channels` and the old `POST /sources` validated `url` with `classify_youtube_url`. In P1 the raw `POST /sources` route was **removed**: sources are created only by `POST /sources/from-url` (YouTube video URLs only; channel/playlist → `422 unsupported_kind`; foreign hosts, `file://`, look-alike hosts → `422 invalid_source`) and `POST /sources/from-transcript` (`reference_url` must be http(s) and is stored as text, never fetched). Update schemas cannot change `url`. |
| KI-13 | Transcripts | **Resolved in P1 (2026-10-01).** Transcript versions are created only by the ingestion service (`POST /transcripts`, `PATCH /transcripts` and `DELETE /transcripts` no longer exist; `/transcripts` is read-only). Each new version flips `is_current` (partial unique index `uq_transcripts_current`); identical content with the same `normalizer_version` is a no-op. A failed attempt stays as a non-current history row once a newer version succeeds, and a failed transcript never replaces a ready one. |
| KI-14 | Sources | **Resolved in P1 (2026-10-01).** `source_videos.url` is nullable and `kind` (`youtube`/`transcript`) was added. An uploaded transcript is `platform='upload'`, `external_id` = its content fingerprint, `url` NULL, with the optional `reference_url` kept in `metadata`. |
| KI-15 | Ingestion | **Resolved in P1 (2026-10-01).** `extract()` stays metadata-only; the new `fetch_transcript()` retrieves captions without downloading media (the service composes the two). Nothing in the library fetches audio, and the faster-whisper adapter remains unwired, so a video without captions ends as `transcript failed (no_captions)` and the user is offered a transcript upload. Cost: each `fetch_transcript` call repeats yt-dlp's metadata extraction. |
