# ADR-007: Illustrations + camera motion, rendered deterministically

> Videos are built from generated stills with camera movement, narration, subtitles and music — not per-scene AI video.

## Status

Accepted · 2026-10-01 · **Partially implemented** — timeline builder, Remotion `Basic` composition and a verified sample render exist; image generation, audio and the project render workflow are Planned — not implemented.

## Context

AI video clips are expensive, slow, inconsistent and hardware-hungry. Stills with purposeful motion, strong narration and editing can feel like a professionally edited documentary and are cheap to regenerate per scene.

## Decision

1. Visuals are **illustrations** (generated by an `ImageGenerator`), animated by deterministic **camera motion** (zoom/pan/tilt) and transitions.
2. The pipeline is `SceneSpec[] → build_timeline → Timeline JSON → Remotion composition → MP4` ([timeline-specification](../media/timeline-specification.md)).
3. **Remotion** owns programmable composition, preview and — today — encoding (the same composition runs in the web Player and the CLI renderer, and Remotion ships its own bundled `ffmpeg`/`ffprobe`). **System FFmpeg is not required** for rendering; no StoryWeaver code invokes it. FFmpeg's role beyond Remotion's encoder (audio mixing, ducking, loudness normalisation, post-processing) is **Decision pending** until the audio pipeline exists ([ffmpeg](../media/ffmpeg.md)).
4. On-screen time per image is typically about 5–7 seconds, but it is a **default, not a rule**; narration, pacing, visual complexity, emotional beat and transitions decide. The code's fallback estimate clamps to 2–7 s only when audio length is unknown.
5. One image may serve multiple shots; new images are generated only when needed (cost control — [ai-cost-strategy](../ai/ai-cost-strategy.md)).
6. Rendering is local. **Timeline JSON is deterministic** (same scenes → same timeline) — *Implemented and unit-tested*. **Render reproducibility** (same timeline → same video) is the *goal* but **Planned / unverified**: one sample render exists and no test compares renders. Render inputs are intended to be snapshotted in `renders.timeline` (the table exists; no render workflow writes it).

## Alternatives considered

Per-scene AI video generation (cost/consistency); FFmpeg-only composition (weaker preview and component reuse); MoviePy (less suited to a React preview).

## Consequences

- Visual consistency relies on the character/visual bible and reference images, not on motion models ([image-consistency](../media/image-consistency.md)).
- Remotion's licence may apply to the owner's organisation ([content policy](../product/content-policy-and-source-usage.md)).
- Render needs a headless Chrome (downloaded by Remotion on first render); the encoder is Remotion's bundled one. Render time on CPU-only hardware for a 10–15 minute video is **unmeasured**.
- Local asset files are not served over HTTP, and the composition uses `<Img src>` directly, so asset resolution for render is **Decision pending** ([KI-17](../reference/status.md#known-issues-and-limitations)).

See [rendering-architecture](../architecture/rendering-architecture.md), [remotion](../media/remotion.md), [camera-motion](../media/camera-motion.md).

## Revisit when

The audio pipeline is built (decide FFmpeg's role), render time on target hardware is measured, or a stronger render-reproducibility check is added.
